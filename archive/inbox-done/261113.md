
L4 - web (nginx) - was (docker) 구성에서 접속자 실 IP 를 알기 위해 필요한 구성은??

- 교사의 요청은 앱에 도착하기 전에 **L4 장비에서 한 번, nginx에서 한 번 "대신 전달"**됩니다. 대신 전달할 때마다 보낸 사람 주소가 전달한 장비 주소로 바뀝니다. 그래서 원래 교사 IP는 **헤더라는 메모**에 적어서 넘겨야 합니다. 지금은 그 메모를 이어 주는 설정이 빠져 있습니다.

**L4 (부하분산 장비)**

- 맨 앞에서 요청을 받아 WEB01·02로 나눠 줍니다.
- HTTPS 암호도 여기서 풉니다(TLS 종료). 암호를 풀기 때문에 HTTP 헤더를 추가할 수 있습니다.

**VIP**

- 교사가 접속하는 대표 주소입니다. 운영은 `10.232.143.175:443`입니다.

**SNIP**

- L4가 뒤쪽 서버로 연결할 때 쓰는 자기 주소입니다. 운영은 `.173`이고 tcpdump로 확인했습니다(TB는 `.248`).
- 그래서 nginx 입장에서는 **모든 요청이 `.173`에서 온 것**으로 보입니다.

**프록시 (리버스 프록시)**

- 요청을 대신 받아 대신 전달하는 서버입니다. L4와 nginx가 둘 다 프록시입니다.
- 대신 전달하는 순간 출발지가 자기 주소로 바뀝니다.

**remote_addr / getRemoteAddr / peerIp**

- 모두 "바로 앞에서 연결해 온 상대"의 주소를 가리키는 이름입니다.
- nginx의 `$remote_addr`는 `.173`이고, 앱의 `getRemoteAddr()`는 WEB 서버 주소입니다. 앱 로그에서는 `peerIp`로 찍힙니다.

**XFF (X-Forwarded-For)**

- 프록시가 "원래 보낸 사람"을 적는 표준 메모입니다. 프록시를 지날 때마다 뒤에 덧붙습니다.
- 예를 들면 이렇게 쌓입니다.
    - L4가 적으면: `203.0.113.10`
    - nginx가 `.173`을 덧붙이면(`nginx.prod.conf:76`): `203.0.113.10, 10.232.143.173`

**헤더 위조**

- XFF는 교사 PC가 직접 써서 보낼 수도 있습니다.
- 예를 들어 PC가 `X-Forwarded-For: 1.2.3.4`를 붙여 보내면, L4가 뒤에 덧붙여서 `1.2.3.4, 203.0.113.10`이 됩니다.
- **맨 앞 값을 믿으면 `1.2.3.4`에 속습니다.** 플랫폼이 이 방식입니다.
- 믿을 수 있는 값은 **우리 L4가 덧붙인 값(맨 뒤)**뿐입니다.

**X-AIS-Trusted-Source-IP**

- 생기부 전용 메모입니다.
- 설계는 이렇습니다. nginx가 교사 PC가 보낸 같은 이름의 헤더는 지우고, 자기가 확인한 교사 IP **하나만** 적어 앱에 넘깁니다.
- 로컬 Apache 설정에는 들어 있지만(`apache.local.conf:86,89`), **운영 nginx에는 없습니다.**

**신뢰 프록시 CIDR (`ACCESS_LOG_TRUSTED_PROXY_CIDRS`)**

- 앱이 "이 주소에서 온 요청의 X-AIS 메모만 믿겠다"고 정해 두는 목록입니다. WEB01·02 주소를 넣어야 합니다.
- CIDR은 IP 범위를 적는 방식이고, `/32`는 한 대를 뜻합니다.
- 지금은 **비어 있어서 아무 메모도 믿지 않습니다.**

**trustedOriginIp**

- 앱이 위 조건을 모두 통과했을 때만 채우는 "교사 IP"입니다. 조건은 세 가지입니다.
    1. 신뢰 목록에 있는 nginx에서 왔다.
    2. X-AIS 헤더가 정확히 1개다.
    3. 값에 쉼표가 없다.
- 하나라도 어긋나면 비어 있게 되고, 이때 LAMP 로그인·조회 기록은 **아예 쓰지 않습니다.**
- 앱은 위조 위험 때문에 XFF를 일부러 보지 않습니다.

**realip 모듈**

- nginx가 “`.173`에서 온 요청이면 XFF의 값을 진짜 출발지로 본다”고 처리하게 해 주는 기능입니다(`set_real_ip_from`).
- 그런데 운영 nginx 빌드 스크립트에는 이 모듈이 없습니다. 빌드 옵션이 `--with-http_ssl_module` 하나뿐입니다(`nginx-build.sh:15-23`).
- 쓰려면 WEB 3대를 다시 빌드해야 합니다. 대안으로, 재빌드 없이 기본 기능(`map`)으로 XFF의 맨 뒤 값을 뽑아 쓸 수 있습니다.

**allow / deny**

- `nginx.prod.conf:60-62`에 “81 포트는 L4 SNIP만 받는다”는 줄이 있는데, 지금은 **주석 처리**되어 있습니다.
- 이 줄이 켜져 있어야 “XFF 맨 뒤 값 = L4가 쓴 값”이라고 믿을 수 있습니다. 꺼져 있으면 누군가 81로 직접 붙어서 XFF를 꾸밀 수 있습니다.

### 지금 실제로 벌어지는 일

1. 교사(`203.0.113.10`)가 로그인합니다.
2. L4가 XFF를 넣는지는 **확인하지 못했습니다.**
3. nginx는 XFF를 그대로 넘기지만, X-AIS 메모는 만들지 않습니다.
4. 앱은 WEB 주소만 봅니다. 신뢰 목록도 비어 있어서 교사 IP를 알 수 없습니다.
5. 그 결과 **LAMP 로그인·조회 기록은 생략**되고, 변경·로그아웃 기록은 IP 빈 값으로 남습니다.

### 고칠 곳 3군데

1. **L4:** 교사 IP를 XFF에 넣는 설정이 켜져 있는지 L4 담당에게 확인하고, 꺼져 있으면 요청합니다.
2. **nginx:** 두 가지를 합니다.
    - SNIP만 받는 allow 줄을 켭니다.
    - XFF 맨 뒤 값을 `X-AIS-Trusted-Source-IP`로 넣습니다. 이 헤더는 nginx가 새로 쓰므로, 교사 PC가 같은 이름으로 보낸 값은 덮어써집니다.
3. **앱 env:** `ACCESS_LOG_TRUSTED_PROXY_CIDRS=<WEB01 IP>/32,<WEB02 IP>/32`를 넣습니다.
