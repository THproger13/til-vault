# 개발 외 주제 블로그: 발행과 복습 프로세스

**개발 외 주제는 관문 1 통과 후 별도 사이트로 운영하고, 분야를 세 유형으로 나눠 복습이 필요한 분야에만 복습 루프를 붙인다.** 개발 블로그 발행 리듬이 깨지면 이 채널부터 멈춘다.

## 분야 유형

| 유형 | 예 | 복습 카드 | 도표 | 템플릿 | 주 수익 |
| --- | --- | --- | --- | --- | --- |
| 복습형 (개념이 쌓이는 분야) | 금융·세금 제도, 경제 개념, 명리학 이론, 외국어 | 있음 | **필수** | 기술 블로그 템플릿 응용 | 광고 |
| 도구형 | 대출·복리·실수령액 계산기, 만세력 | 해설 글만 복습형 규칙 | **필수** (계산 흐름) | 도구 + 해설 글 | 광고 |
| 발행형 | Apple 기기·게임 리뷰, 사용기 | 없음 | 선택 | 리뷰 템플릿 | 제휴 |

## 복습형 템플릿 (좋은 기술 블로그 구조 응용)

1. **검색 의도가 드러나는 제목**: 질문이나 키워드 중심
2. **요약 3줄**: 결론부터
3. **어떤 상황에서 필요한가**: 기술 글의 "문제 상황"에 해당
4. **원리와 도표 (필수)**: 구조도, 흐름도, 비교표 중 하나 이상
5. **예시**: 숫자를 넣은 계산이나 사례. 기술 글의 "직접 해본 결과"에 해당하며 직접 쓴다
6. **자주 하는 오해와 함정**
7. **출처**: 공식 기관, 법령, 원전 우선
8. **기준일**: 제도·세율·금리처럼 바뀌는 정보는 언제 기준인지 명시
9. **면책 문구**: 분야별 규칙 (아래)

복습 카드 규칙은 개발과 같다: 카드 하나에 개념 하나, 답은 한 문장, 원문 외 금지. `prerequisite` 관계도 같이 적어 스킬 트리·보스가 그대로 동작하게 한다.

## 프로세스

| 단계 | 개발과 다른 점 | 도구 |
| --- | --- | --- |
| 1. 키워드 조사 | 글을 쓰기 전에 검색 수요부터 확인해 `life/30-ideas/`에 넣는다 | `keyword-research` |
| 2. 수집 | 유형별 인터뷰 질문. 복습형: 무엇을 새로 알았나 / 헷갈린 점 / 어디에 쓰나. 발행형: 무엇을 써봤나 / 좋았던·아쉬운 점 / 누구에게 추천 | `til-interview` (질문 세트 추가) |
| 3. 정리 | `life/` 폴더에 저장, 카드는 복습형만 | `inbox-organize` |
| 4. 사실 확인 | 경험이 아닌 사실은 출처와 기준일을 반드시 붙인다 | `source-check` |
| 5. 발행 | 기존 검사 + 분야별 규칙 검사 | `publish-guard` |
| 6. 복습 | 같은 SR 플러그인, 덱을 `#flashcards/life` 태그로 분리 | Obsidian SR |
| 도구형 추가 | 공식 명세 → 테스트 케이스 통과 → 페이지 생성 | `tool-page-builder` |

**분야별 발행 규칙**

- 금융·세금: "참고용이며 실제 조건은 금융기관·세무 전문가에게 확인" 면책, 기준일 필수
- 건강: 의료 조언 금지, 다루지 않는 것을 기본으로
- 리뷰: 제휴 링크가 있으면 대가를 받는다는 문구 (공정위 추천·보증 지침)
- 명리학: 오락·참고 목적 표기

## 볼트와 설정

```
vault/life/
├── 00-inbox/
├── 10-concepts/   ← 복습형·도구형 해설
├── 20-posts/
└── 30-ideas/      ← 키워드 조사 결과
```

```markdown
---
channel: life
field: finance          # finance | saju | apple | game ...
type: concept           # concept | tool | review
cards: true             # 복습형만 true
sources: []
as_of: 2026-11-01       # 기준일
status: draft
---
```

그래프 뷰와 Bases 대시보드는 `path:life`로 개발 지도와 분리해서 본다. 말투 가이드도 `life/20-posts/` 발행본으로 따로 만든다 (기술 글과 말투가 다르므로).

## 채널 운영

- **별도 도메인과 브랜드**: 개발 블로그의 포트폴리오 가치를 흐리지 않도록 분리한다. 실명 공개 여부는 시작 전에 정한다.
- **시작 조건**: 관문 1 통과. 도구형 페이지 3개 + 해설 글로 시작한다. 첫 분야는 금융(광고 단가가 높은 편)과 명리학(관심사, 검색 수요) 중 하나만 고른다.
- **리듬**: 격주 1편 (글 또는 도구 페이지). 개발 블로그 주 2회가 우선이다.
- **관문**: 3개월 뒤 페이지 15개, 검색 노출이 생긴 페이지 비율로 계속 여부를 판단한다.

## 리스크

| 리스크 | 대응 |
| --- | --- |
| 돈·건강 주제는 검색엔진이 전문성과 출처를 더 엄격하게 봄 | 해설 글보다 도구 중심, 출처·기준일 필수 |
| AI 대량 생산 글로 판정 | 글마다 직접 만든 도구나 직접 쓴 예시 포함 |
| 채널이 둘이 되면서 번아웃 | 개발 블로그 우선, 리듬이 깨지면 이 채널부터 중단 |
| 제도 변경으로 글·계산기가 틀려짐 | `as_of` 기준일이 1년 지난 노트를 월간 리포트에서 점검 |
