# 블로그 초안

먼저 `style-guide.md`와 `20-posts/published/`의 최근 발행본 2편(없으면 style-guide의 예시)을 읽는다.

입력: `status: blog`이고 `sensitivity: public`인 노트(묶음이면 여러 개).

**묶음 노트(hub)로 쓰는 긴 글**: 묶음 노트의 "## 개요"를 글 도입과 요약의 뼈대로, "## 하위 개념 지도"를 전체 그림 도표로 쓴다. 하위 답 노트는 `prerequisite` 순서(선행 개념을 먼저)로 한 섹션씩 놓고, 각 섹션은 그 답 노트의 풀이·예제·도표·출처를 그대로 가져온다. 하위 노트끼리 겹치는 설명은 한 번만 쓰고 뒤 섹션에서 앞 섹션을 가리킨다. 씨앗은 "다음에 볼 개념" 목록에 이름과 한 줄 설명만 쓴다. `source_notes`에는 묶음 노트와 들어간 답 노트를 모두 적는다. 사용자가 대화에서 노트를 직접 지정하면 `draft`·`reviewed`여도 쓰되, 먼저 그 노트를 `blog`로 바꿀지 물어본다. `post_format`이 `none`이면 `short`로 쓴다.

`templates/post.md` 순서를 지킨다.
1. 검색 의도가 드러나는 제목 (문제·키워드 중심)
2. 요약 3줄 (결론부터)
3. 문제 상황 (재현 가능한 맥락, 버전, 증상. 회사 정보 일반화)
4. 원리와 Mermaid 도표 (필수)
5. 해결과 선택지 비교, 트레이드오프
6. 직접 해본 결과: 원본 메모를 뼈대로 쓴다. 원본 메모에 없는 수치·경험을 지어내지 않는다. 비어 있으면 "[직접 작성]"으로 둔다
7. 함정과 주의점
8. 참고 자료 (공식 문서 우선, 실제로 확인한 링크만)
9. 작성일·버전·수정 이력

답 노트의 약어·명령어·옵션 풀이와 "## 코드 예제"를 그대로 가져온다. 초안 단계에서 새 예제나 새 풀이를 만들지 않는다. 노트에 풀이가 빠져 있으면 초안 맨 위에 "노트 보강 필요: …"를 적는다. 업무 코드는 어떤 경우에도 넣지 않는다.

짧은 글 최소 기준: 도표 1개, 경험 문단 1개, 공식 출처 1개. 못 채우면 초안 맨 위에 "발행 보류: 사유"를 적는다.

`20-posts/drafts/YYYY-MM-DD-slug.md`로 저장한다. 초안 맨 위 속성에 `source_notes: ["[[노트명]]"]`을 남긴다. 원본 노트는 `status: drafted`, `drafted_at`, `draft_path`만 바꾸고 본문은 고치지 않는다. 사용자가 할 일 3가지(경험 문단 다듬기, 도표 확인, publish-guard)를 알려준다.
